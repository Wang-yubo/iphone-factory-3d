# 苹果手机生产线 3D 模拟器 · 项目提示词（v1.1 已定稿）

> 用途：本文档是交给 AI 编程助手（或外包开发者）的需求规格 + 提示词。先确认本文档，再开始写代码。
> 版本：v1.1（已定稿）。状态：**仅提示词与规格，未创建任何项目代码**。

---

## 0. 一句话定义

一个跑在浏览器里的 3D 手机工厂：玩家亲手把原料投进产线料仓，按下启动键，然后看着手机从铝锭、玻璃、芯片开始，在传送带上依次经过 7 个工站，被机械臂加工、被相机检测、被装箱，最后变成一台成品 iPhone 摆在出货区。

## 1. 三个不可妥协的原则

1. **"投料"必须是手动且是核心操作。** 开局所有料仓为空，不投料就一台都产不出来。投料要有动作感（抓取、搬运、落料），不是点一下数字 +1 就完事。
2. **产线必须是"流动"的，不是进度条。** 每一台半成品都是场景里真实存在的 3D 物体，沿传送带移动、在工位上被加工、被判定良品/不良品。禁止用 UI 进度条假装生产。
3. **看得见的因果。** 玩家做的每一个动作，都要在 3D 场景里立刻有对应后果：投料→料仓变满；启动→传送带转、机械臂动；缺料→该工站红灯、整线停；检测不合格→产品进红色回收箱。

## 2. 可直接粘贴的精简提示词

```text
你是一名资深 Three.js / React Three Fiber 工程师兼游戏设计师。请为我从零构建一个可运行的 3D 网页项目：
「苹果手机生产线模拟器」。

【核心体验】
玩家是工厂产线工程师。开局所有工站料仓为空，玩家必须手动把 7 种原料
（铝锭、主板基板、SoC 芯片、玻璃面板、电池、摄像头模组、包装盒）投入对应工站的料仓，
然后按下「启动产线」。产线上每一台半成品都是真实 3D 物体，沿传送带依次经过 7 个工站：

1 冲压成型（铝锭→机壳，2.5s）
2 主板贴装（主板基板+芯片→主板总成，3.0s）
3 屏幕贴合（玻璃面板+机壳→屏装机壳，3.0s）
4 电池装配（电池+屏装机壳→电池总成，2.0s）
5 相机装配（3×摄像头模组+电池总成→半成品，2.5s）
6 功能检测（半成品→良品/不良品，4.0s，良率 92%）
7 包装（良品+包装盒→成品手机，2.0s）

每个工站有独立料仓（容量 12）和入口缓存（容量 3）；缺料则该工站红灯停线并弹出提示，
补料后自动恢复；缓存满则上游阻塞。成品手机计数 +1 并落到出货区货架上。

【必须实现】
- 全 3D 场景：车间地面、7 个工站、传送带、机械臂、料仓、出货货架、悬挂灯带
- 手动投料：从右侧原料仓库面板点击/拖拽原料到场景中的料仓，有抛物线落料动画和音效；
  也支持「批量补料 +5」「按 BOM 一键配齐」
- 传送带真实运转，零件沿带移动，机械臂抓取到加工台、做加工动画、再放回
- 检测站良率判定：不良品变红、被推入回收箱，不计数
- HUD：原料库存、各站料仓储量、在制品数、成品数、良率、UPH（每小时产能）
- 控制：启动/暂停、1x/2x/4x 变速、重置、相机预设（全景/俯视/跟随单台手机/工站特写）
- 缺料、堵料、停线都要有明确的视觉 + 文字提示
- 订单面板：同时 1 条进行中 + 2 条排队，按交付台数结算并自动接下一单

【技术约束】
- Vite + React + TypeScript + three + @react-three/fiber + @react-three/drei + zustand
- 所有几何体程序化生成（BoxGeometry/CylinderGeometry/LatheGeometry 等），禁止依赖任何外部
  模型文件、贴图、CDN 资源，保证 clone 下来就能跑
- 逻辑与渲染分离：产线状态机放在 zustand store 里，用固定时间步推进；3D 只做插值渲染
- 60fps 为目标，桌面 Chrome 为基准，窗口宽度 1280 以上
- TypeScript 严格模式无报错，`pnpm build` 通过，控制台无错误

【美术方向】
干净的工业极简风：深灰地面、白色铝合金产线、银灰机壳、苹果式留白，
点缀青蓝色科技光与琥珀色警示灯；柔和面光 + 轻微 Bloom，不要赛博朋克霓虹堆砌。

【交付要求】
分阶段交付，每个阶段结束我都能 `pnpm dev` 打开看到可运行的结果：
P1 场景与相机 → P2 传送带与物料流动 → P3 原料系统与投料交互 → P4 工站加工与良率
→ P5 产出、订单、统计与 HUD → P6 光影、音效与打磨。
现在只做 P1，并在开始前先用 10 行说明你的场景布局与坐标规划。
```

## 3. 完整规格

### 3.1 目标用户与体验曲线

| 阶段 | 时间 | 玩家在做什么 | 情绪 |
|---|---|---|---|
| 好奇 | 0–30s | 转动镜头看工厂，发现所有料仓是空的 | "这是要我干活" |
| 上手 | 30s–2min | 把铝锭拖进 1 号站，按下启动，看第一块机壳做出来 | "哦，通了" |
| 忙碌 | 2–5min | 一边补料一边盯着哪个站红了，节奏开始出现瓶颈 | "我得算着投" |
| 成就 | 5min+ | 第一台成品手机落到货架上，计数跳出 1 | "再来十台" |

**验收的情绪标准**：第一台成品下线时，必须有一个明确的"达成时刻"——镜头轻推、货架落位、计数器跳动、音效上扬。

### 3.2 核心循环（状态机）

```
[空仓] --手动投料--> [就绪] --启动--> [运行] --缺料/堵料--> [停线]
                                     |                      |
                                     |<----补料/清堵--------|
                                     v
                              [成品入库] --> 回到运行
```

全局状态（zustand）：
- `lineState`: `idle | running | paused | starved | blocked`
- `speed`: `1 | 2 | 4`
- 每种原料 `stock`（仓库）、每站 `bin[2]`（料仓 A/B）
- 每站 `buffer`（入口缓存队列）、`processing`（当前加工对象）
- `wip[]`（传送带上的在制品，含 id、工位进度、型号状态）
- `finished`、`defects`、`totalProduced`、`totalStartedAt`
- `eventLog[]`（最近 30 条，用于 HUD 滚动播报）

时间推进：`useFrame` 中累加 `delta * speed`，交给纯函数 `tick(state, dt)` 推进，保证变速与暂停不影响逻辑正确性。

### 3.3 场景布局

俯视示意（X 轴向右为产线方向，Z 轴向前为观众方向，Y 向上）：

```
                                    ┌─ 出货货架（成品手机阵列）
                                    │
 ┌──────┐  ┌────┐  ┌────┐  ┌────┐  ┌────┐  ┌────┐  ┌────┐  ┌────┐
 │ 原料 │→ │ S1 │→ │ S2 │→ │ S3 │→ │ S4 │→ │ S5 │→ │ S6 │→ │ S7 │→ 装箱
 │ 仓库 │  │冲压│  │主板│  │贴合│  │电池│  │相机│  │检测│  │包装│
 └──────┘  └────┘  └────┘  └────┘  └────┘  └────┘  └────┘  └────┘
              每站：传送带上方 = 料仓（悬浮标签 x/12）
                    传送带外侧 = 加工台 + 机械臂
                    检测站旁 = 红色不良品回收箱
```

- 地面：24 × 14 的车间地板，深灰哑光，带 1m 网格线和产线安全黄线
- 产线：一条 22m 长的传送带，宽 0.9m，离地 0.9m，带侧边导轨
- 工站间距 3m，站体为白色金属框架 + 半透明防尘罩
- 相机初始位置：`(14, 9, 14)` 看向 `(0, 1, 0)`，视野能装下整条线

### 3.4 工站与数值

| # | 工站 | 输入 A | 输入 B | 产出 | 节拍 | 良率 | 动画要点 |
|---|---|---|---|---|---|---|---|
| 1 | 冲压成型 | 铝锭 | — | 机壳 | 2.5s | 99% | 冲压头下压、火星粒子、机壳从模具顶出 |
| 2 | 主板贴装 | 主板基板 | SoC 芯片 | 主板总成 | 3.0s | 98% | 贴片头快速点阵下落、芯片吸附、蓝光扫描 |
| 3 | 屏幕贴合 | 玻璃面板 | 机壳 | 屏装机壳 | 3.0s | 97% | 玻璃从上方缓缓压下、真空吸附、UV 紫光闪 |
| 4 | 电池装配 | 电池 | 屏装机壳 | 电池总成 | 2.0s | 99% | 机械臂翻转、电池推入、螺丝刀旋转 |
| 5 | 相机装配 | 3× 摄像头模组 | 电池总成 | 半成品 | 2.5s | 96% | 三个模组依次吸附落位、镜头对焦红光 |
| 6 | 功能检测 | 半成品 | — | 良品 / 不良品 | 4.0s | 92% | 探针下压、屏幕亮起跑自检、绿/红判定灯 |
| 7 | 包装 | 良品 | 包装盒 | 成品手机 | 2.0s | 99.5% | 盒盖合拢、封膜、贴标、滑入货架 |

设计意图：
- **瓶颈在 6 号检测站（4s）**，理论 UPH = 900，实际受缺料与缓存影响低得多。玩家会自然发现"要保证检测站永远有料"。
- 每个工站有 2 个料位（A/B），1 号站只用 A；2、3、4、5、7 站需要 A+B 都有料才能开工。
- 料仓容量 12；入口缓存 3；缓存满 → 上游阻塞（`blocked`），传送带该段暂停，前段堆积。
- 不良品率按站独立判定，累计良率在 HUD 实时显示。

### 3.5 物料与 BOM

7 种原料：

| 原料 | 图标色 | 单台用量 | 供应工站 |
|---|---|---|---|
| 铝锭 | 银灰 | 1 | S1 |
| 主板基板 | 深绿 | 1 | S2 |
| SoC 芯片 | 金 | 1 | S2 |
| 玻璃面板 | 冰蓝 | 1 | S3 |
| 电池 | 墨黑 | 1 | S4 |
| 摄像头模组 | 紫 | 3 | S5 |
| 包装盒 | 米白 | 1 | S7 |

→ **单台手机完整 BOM = 9 个物料件**。「按 BOM 一键配齐」= 按上表把每个料仓补到"刚好够 1 台"的量。

半成品形态要能被肉眼区分（用几何体差异 + 颜色区分，不要靠文字标签）：
裸机壳（薄板） → 主板总成（绿色小板+金点） → 屏装机壳（带蓝色屏幕面） → 电池总成（带黑色方块） → 半成品（带 3 个镜头圆点） → 成品（圆角白色长方形 + 屏幕微光）。

### 3.6 手动投料交互（核心，重点做）

三种粒度，从"有手感"到"有效率"：

1. **单件投料（拖拽）**：从右侧原料仓库面板按住某原料，出现半透明幽灵模型跟随鼠标；拖到目标料仓上方高亮吸附，松手 → 料仓"咔"一声落料，库存 -1，仓内 +1。拖错工站 → 料仓抖红 + "该原料不适用此工站"。
2. **点击投料**：先点原料图标（选中态），再点场景中料仓 → 投 1 件。适合移动端。
3. **批量**：料仓悬浮标签旁有 `+5` 和 `满` 按钮；仓库面板有「按 BOM 配齐」。

约束与失败反馈：
- 料仓满 → 拒绝投入，飘字"料仓已满"，料仓边框闪琥珀色
- 仓库库存不足 → 按钮置灰，飘字"库存不足"
- 投料成功：料仓数字滚动 +1、轻微弹性缩放、机械落料音效（`thock`）
- 全局统计：本次共投料 N 件 / 浪费 M 件（投错被拒）

> 关键细节：**开局所有料仓为 0**，且首次进入有一条 3 步引导（高亮 1 号站料仓 → 高亮启动按钮 → 高亮成品货架），可跳过。

### 3.7 视觉与美术

**风格**：工业极简 × 苹果审美。参考 Apple Park 的干净感，而不是赛博朋克。

- 主色：`#F5F6F7` 白铝、`#2A2D31` 深灰地面、`#8E9399` 中灰结构件
- 强调色：`#2FB8FF` 青蓝（运行/数据）、`#FFB020` 琥珀（警告/缺料）、`#FF4D4F` 红（故障/不良）、`#34D399` 绿（合格/完成）
- 材质：`MeshStandardMaterial`，金属件 `metalness 0.8 / roughness 0.35`，地面 `roughness 0.9`，防尘罩用 `MeshPhysicalMaterial` + `transmission 0.9`（性能不够就退回半透明）
- 灯光：1 个半球光打底 + 2 个大面积平行光（主光 + 补光）+ 沿产线的 4 根条形灯管（自发光 + 点光）
- 后处理：Bloom（强度 0.35）+ 轻微 Vignette；抗锯齿开 4x MSAA，不开 SSAO（保帧率）
- 细节加分项（有余力再做）：传送带滚动贴图、地面反射、机械臂运动拖影、成品屏幕上的微光渐变、空气中缓慢漂浮的尘埃粒子

**不做**：写实 PBR 贴图、人物角色、室外环境、复杂粒子爆炸。

### 3.8 相机与镜头

- 轨道控制：`OrbitControls`，限制 `polarAngle ∈ [0.15π, 0.48π]`、`distance ∈ [6, 30]`、禁止穿地
- 预设视角（HUD 底部按钮，切换时 0.8s 缓动）：
  1. 全景 `(14, 9, 14)`
  2. 俯视 `(0, 18, 0.01)`
  3. 侧视产线 `(0, 4, 16)`
  4. 出货区特写 `(10, 3, 8)`
- 跟随模式：点任意在制品 → 相机 0.6s 推到该物料的跟随机位，直到它变成成品或玩家退出
- 点击工站 → 聚焦该站，右侧面板切到该站详情（料仓、缓存、节拍、良率、累计产出）

### 3.9 HUD / UI

布局：左侧细长状态栏 + 底部控制条 + 右侧原料仓库 + 顶部事件滚动条。

- **顶部**：`运行中 / 已停线` 状态胶囊、总产出、UPH、累计良率；一条滚动的事件日志（"S4 缺料停线"）
- **左侧**：7 个工站迷你卡片（站号、状态灯、料仓 x/12、缓存 x/3、当前加工进度环）
- **右侧**：原料仓库，7 个原料卡片（图标、名称、库存、拖拽把手）
- **底部**：`▶ 启动 / ⏸ 暂停`、速度 `1x 2x 4x`、`重置`、视角预设、`按 BOM 配齐`、帮助 `?`
- **右上**：订单卡（客户、`7/12 台`、剩余时间、预计积分）+ 排队订单 + 评价等级
- **中央浮层**：缺料/堵料的横幅提示（3s 自动消失，同类合并）
- 字体：系统无衬线；数字用等宽（`tabular-nums`），避免跳动
- UI 用 HTML/CSS 叠在 canvas 上（不用 drei 的 Html 做面板），保证清晰度与可访问性

### 3.10 音效

用 WebAudio 程序化合成或极小体积的 base64 音频，**不要外链**：
- 落料 `thock`、启动 `whoosh`、机械臂伺服 `whirr`、检测通过 `ding`、检测失败 `buzz`、成品下线 `chime`
- 首次交互后才初始化 AudioContext（浏览器策略），提供静音开关

### 3.11 技术栈与工程约束

```
vite + react 18 + typescript + three + @react-three/fiber + @react-three/drei
+ @react-three/postprocessing + zustand + tailwindcss（可选）
```

硬约束：
1. **零外部资源**：不下载 glTF/贴图/字体文件，所有几何体程序化生成，图标用内联 SVG。
2. **状态与渲染分离**：`sim/` 目录放纯函数逻辑（可单测），`scene/` 只负责读 store 渲染。
3. **固定步长**：模拟用 `1/30s` 固定步长累积推进，渲染用插值，变速只改步长次数。
4. **对象池**：传送带上的零件最多同时存在约 30 个，用数组管理 `key`，不用 `useState` 逐个创建。
5. **无内存泄漏**：所有 `useFrame` 的副作用在卸载时清理。
6. 单文件不超过 300 行；`App.tsx` 只做布局拼装。

### 3.12 性能预算

| 指标 | 目标 |
|---|---|
| 桌面 Chrome 帧率 | ≥ 55fps（1080p） |
| Draw calls | < 150 |
| 三角形数 | < 200k |
| 首屏可交互 | < 2s（本地 dev） |
| 内存 | < 300MB |

降级策略：低端设备自动关闭 Bloom、关闭防尘罩透明、减少机械臂分段数（用 `useDetectGPU` 或简单 FPS 采样自适应）。

### 5.1 订单系统规格

设计目标：给"无限生产"一个**结束点和目标感**，同时**不新增操作负担**——订单不要求玩家做新动作，它只是把"产出成品"这件事变成"按时交够数量"。

**数据模型**

```ts
type Order = {
  id: string
  client: string          // 客户名：星河零售 / 蓝湖通信 / 环球渠道
  model: 'iPhone 17 Pro'
  qty: number             // 需要台数
  delivered: number       // 已交付
  timeLimitSec: number    // 游戏内时限（1x 速度下计时，变速同步缩放）
  elapsedSec: number
  reward: number          // 积分
  state: 'active' | 'done' | 'failed'
}
```

**规则**

- 开局自动接第 1 单；同时 1 条 `active`，队列最多 2 条，完成即自动接下一单（队列空时生成随机新单）。
- 成品下线 → `delivered + 1`；`delivered === qty` → 立即结算：`reward × 时间余量系数`（余量 >50% 得 ×1.2，>20% 得 ×1.0，否则 ×0.8）。
- 超时未交够 → 标记 `failed`，`评价 -1`，自动接下一单。**不卡死产线，不清空库存。**
- 评价等级按 完成单数 / 失败单数 实时计算：`S(失败≤0) / A(失败≤1) / B(其他)`，显示在 HUD 右上。
- 暂停时计时器同步暂停；`4x` 速度时计时器按 4 倍速走（与产线一致）。

**首批订单数值**（默认节拍下，理论 UPH 900，实际受投料影响约 300–500）

| 订单 | 台数 | 时限 | 基础积分 | 考察点 |
|---|---|---|---|---|
| 试用单 | 6 台 | 120s | 60 | 学会投料与启动 |
| 首单 | 12 台 | 180s | 140 | 学会按 BOM 配齐、盯缺料 |
| 加急单 | 8 台 | 90s | 120 | 学会提前备料、抢在停线前补料 |
| 大单 | 20 台 | 300s | 260 | 稳定运行、减少停机 |

**UI 表现**

- HUD 右上角订单卡：客户名、`7 / 12 台`进度条、剩余时间（<30s 变琥珀，<10s 变红并脉冲）、预计积分。
- 队列订单以两行小卡片叠在下方，只显示 `客户 · 台数 · 时限`。
- 结算瞬间：订单卡翻转为"已完成 +积分"并上飘消失；失败则抖动变红 3s。
- 交付动作在场景里要有对应：成品从货架被"打包"飞向左侧出货口（0.5s 缓动），不要只在 UI 上加数字。

**验收**

- [ ] 不投料时订单倒计时照走，玩家能直观感到"停线 = 亏时间"
- [ ] 完成订单的瞬间，场景与 UI 同时给出反馈
- [ ] 任意时刻最多 1 条 active，不存在同时结算两条
