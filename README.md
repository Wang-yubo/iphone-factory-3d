# iPhone 生产线 · 3D 智能工厂

**[▶ 在线体验](https://wang-yubo.github.io/iphone-factory-3d/)** · 桌面 Chrome / Safari，1280px 以上宽度最佳


一个跑在浏览器里的 3D 手机工厂模拟器：手动投料 → 启动产线 → 看着手机从铝锭、玻璃、芯片，
在传送带上依次经过 7 个工站，最终变成一台成品 iPhone 落到出货货架上。

**当前进度：P6 完成 + 多机型换线** — 投料、开线、流动、加工、检测、上架、交付形成闭环，两种机型会触发换线。

---

## 运行

```bash
pnpm install
pnpm dev        # http://127.0.0.1:5173
pnpm test       # 状态机单测（8 个用例）
pnpm build      # 产物在 dist/
```

要求 Node 18+，桌面 Chrome / Safari（1280px 以上宽度体验最佳）。

## 操作

| 操作 | 效果 |
|---|---|
| 左键拖动 / 滚轮 / 右键拖动 | 旋转 / 缩放 / 平移 |
| 点击工站 | 推近到工站特写；再点一次回全景 |
| **拖拽原料 → 料仓** | 投 1 件（松开时料仓会高亮吸附） |
| **点选原料 → 点料仓** | 投 1 件，可连续点 |
| **原料行 `+5`** | 快速补 5 件 |
| `F` / 面板「按 BOM 配齐」 | 每个原料投到对应工站，够做 1 台 |
| 喇叭按钮 | 静音 / 恢复（偏好记在 localStorage） |
| 画质按钮 | 高 / 中 / 低 三档，掉帧会自动降一档 |
| 难度按钮 | 轻松 / 标准 / 硬核（来料缺陷率 0% / 4% / 9%） |
| `空格` | 启动 / 暂停 |
| `1` `2` `3` `4` | 全景 / 俯视 / 侧视 / 出货区 |

## 产线怎么跑

```
S1 冲压 ──机壳──▶ S2 主板 ──▶ S3 贴合 ──▶ S4 电池 ──▶ S5 相机 ──▶ S6 检测 ──▶ S7 包装 ──▶ 入库
  ↑每 2.5s 一件        每站从传送带入口抓件 → 加工 → 放回；出口堵住就先不放行
```

- **工站外观**：40×40 铝型材立柱（方形截面的空心型材，不是平板）+ 上下横梁 + 八个角码 + 顶部走线槽与线束 +
  基座警示带；这堆细节合并成 1 个顶点色几何体，7 个工站共用一份，只多 7 个 draw call
- **机柜**：冲孔侧板（程序化纹理）、控制屏、三颗按钮、散热格栅、工站色灯带
- **在制品外观**：铝锭 → 机壳（带内腔）→ 主板（金色芯片位）→ 屏装机壳（亮屏）→ 电池总成 → 半成品 → 成品，
  全部用圆角盒 + 顶面屏幕表现，俯视角度一眼能看出做到第几站
- **机型**：`iPhone 17 Pro`（摄像头 3 件/台，基准节拍）与 `iPhone 17 Air`（2 件/台、节拍 ×0.86、报酬 ×0.9）
- **换线**：订单机型变了会自动换线 8s，期间 S1 停产、线上旧机型件自然排空；这些"尾料"照常下线但不计入新订单
- **料仓**：每个工站最多两个料位，每仓 12 件（**S5 摄像头 24 件**，正好 8 台 Pro）；S1 吃铝锭、S2 吃主板+芯片、S3 玻璃、S4 电池、S5 摄像头、S7 包装盒；S6 检测不吃料
- **难度**：底部「难度」按钮切换来料缺陷率 —— 轻松 0% / 标准 4% / 硬核 9%。带缺陷的来料一路做到 S6 才被拦下，等于白搭一整台的料
- **投料**：仓库 → 料仓，四条路径（拖拽 / 点选+点仓 / +5 / 按 BOM 配齐），全部走同一个 `feed()`
- **S1 是源工站**：料仓有料就按节拍把机壳放上传送带（没有入场件）
- **S2–S7 是加工工站**：入口取件 → 抬到工位 → 加工 → 放回，同一时刻只加工一件
- **跟车与阻塞**：车距 0.62m，前车不动后车就排队；工位出口被占则加工完也先压着——这就是真实产线的堵料
- **良率**：每站独立判定，整线累计 94.9%；坏件变红飞进工站旁的回收箱，箱上计数 +1
- **缺料停线**：料仓见底 → 工站红灯、抓不到件、上游堵成一条龙；补上料自动复产（会播报"S2 补料完成"）
- **瓶颈在 S6（4s）**：实际 UPH 因此被压在 900 以下，HUD 里能看到真实值

状态机在 `src/sim/engine.ts`，是纯函数 `stepSim(state, dt, opts)`，
渲染层每帧只读状态，HUD 以约 8Hz 读版本号刷新——所以加多少在制品都不会触发 React 重渲染。

## 目录结构

```
src/
  lib/          palette 色板 · layout 坐标 · materials 材质缓存 · flags 调试开关
  sim/          recipes 配方表 · engine 状态机（纯函数） · feed 投料 API · engine.test 单测 · sim 单例
  store/        useFactory：视图/速度/线状态，以及给 HUD 用的 simVersion
  scene/        Factory 主画布 · Loop 固定步长循环 · stationFrame 合并机架 · Station/StationParts 工站与动画
                StationHeads 七站工艺头动画 · Bin 料仓（拖拽目标）· BinPicker 射线拾取
                Conveyor 传送带 · Products 在制品（圆角件 + 顶面屏）· Scrap 回收箱
                Shipments 成品飞行 · Hall 车间骨架 · Ground 地面 · Warehouse 原料仓库
                Shelf 出货区 · CameraRig 相机 · Effects 后期
  ui/           Hud：状态栏 / 工站列表 / 原料面板 / 控制条 / 事件播报 / 帮助
```

## 设计约定（后续阶段必须遵守）

1. **零外部资源**：几何体全部代码生成，环境贴图用 three 自带的 `RoomEnvironment` 烘焙，
   不下载任何模型 / 贴图 / 字体。
2. **逻辑与渲染分离**：`sim/` 是纯函数状态机（可单测），`scene/` 只读状态渲染。
3. **固定步长**：模拟用 1/60s 步进，倍速只改每步的时间缩放；掉帧时不会跳变。
4. **对象池**：在制品用固定 44 个 mesh 的池子，每帧改 position/scale，不做 React 增删。
5. **材质缓存**：`lib/materials.ts` 按参数复用 `MeshStandardMaterial`。
6. **不要用 `backdrop-filter` 做大面积 HUD 背景**：它会让合成器逐帧重算模糊，
   实测把 R3F 渲染循环从 16fps 压到 0.4fps。HUD 一律半透明实色 + 边框。

